# Markdown 测试文档

这是一个用于测试 MarkdownChunkStrategy 的示例文档。

## 第一章：基础概念

本章节介绍基础概念，包含一些普通文本内容。Markdown 分块策略会按照标题层级进行拆分，支持 Level 1/2 父子分块。

### 1.1 什么是 RAG

RAG（Retrieval-Augmented Generation）是一种结合检索和生成的技术。它通过检索相关文档来增强大语言模型的生成能力。

### 1.2 核心组件

RAG 系统通常包含以下核心组件：
- 文档解析器
- 文本分块器
- 向量数据库
- 检索引擎
- 大语言模型

## 第二章：代码示例

下面是一个 Java 代码示例：

```java
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

代码块应该作为原子块被保护，不会被拆分。

## 第三章：表格示例

下面是一个数据表格：

|------|------|------|

表格也应该作为原子块被保护。

## 第四章：超长文本测试（L1级别）

这是一个超长的章节，专门用于测试 Level 1 大块和 Level 2 子块的父子分块机制。当 section 内容超过 maxChunkSize（默认800字符）时，系统应该创建 Level 1 父 chunk，然后对内容进行细化拆分生成 Level 2 子 chunk。

### 4.1 RAG 系统架构详解

RAG（Retrieval-Augmented Generation）是一种将信息检索与文本生成相结合的技术架构。它的核心思想是：在生成回答之前，先从知识库中检索相关的文档片段，然后将这些片段作为上下文提供给大语言模型，从而增强模型的回答能力和准确性。

RAG 系统的主要优势包括：第一，无需重新训练模型即可更新知识库，大大降低了维护成本；第二，可以引用具体的知识来源，提高回答的可信度；第三，减少了模型的幻觉问题，因为回答基于实际检索到的文档；第四，可以处理私有或实时数据，而不受模型训练截止日期的限制。

RAG 系统的典型工作流程如下：用户提出问题后，系统首先将问题转换为向量表示，然后在向量数据库中检索最相关的文档片段。检索到的片段与原始问题一起被送入大语言模型，模型基于这些上下文生成最终的回答。整个过程实现了"检索-增强-生成"的闭环。

### 4.2 向量数据库技术

向量数据库是 RAG 系统的核心组件之一。它专门用于存储和检索高维向量数据。与传统的关系型数据库不同，向量数据库使用向量相似度作为检索依据，而不是精确匹配。

常用的向量数据库包括：PostgreSQL with pgvector 扩展（本项目使用的方案）、Pinecone（托管式向量数据库）、Milvus（开源高性能向量数据库）、Weaviate（支持混合检索的开源数据库）、Chroma（轻量级嵌入式向量数据库）等。

向量相似度计算方法主要有：余弦相似度（Cosine Similarity）、欧几里得距离（Euclidean Distance）、点积（Dot Product）等。其中余弦相似度最为常用，因为它对向量的长度不敏感，只关注方向的一致性。

### 4.3 文本分块策略

文本分块是 RAG 系统中的关键预处理步骤。好的分块策略应该：保持语义完整性，避免将相关内容分散到不同分块；控制分块大小，使其适合向量模型的输入限制；保留上下文信息，便于后续检索和理解。

本项目实现了多种分块策略：MarkdownChunkStrategy 针对 Markdown 文档按标题层级分块；HtmlChunkStrategy 针对 HTML 文档按标签结构分块；CodeChunkStrategy 针对代码文件按类和函数定义分块；LineBasedChunkStrategy 针对日志和 CSV 文件按行分块；StructureAwareChunkStrategy 针对 PDF 和 DOCX 文档按段落分块；RecursiveChunkStrategy 作为通用兜底策略使用递归字符分割。

分块大小的选择需要权衡多个因素：太小的分块可能丢失上下文信息，太大的分块可能包含过多无关内容。通常建议的分块大小在 500-1500 字符之间，具体取决于文档类型和应用场景。

### 4.4 嵌入模型选择

嵌入模型负责将文本转换为向量表示。选择合适的嵌入模型对 RAG 系统的性能至关重要。常用的嵌入模型包括：

BGE（BAAI General Embedding）系列：由北京智源人工智能研究院开发，支持中英文，本项目使用 BGE-small-zh 模型。该模型体积小、速度快，适合本地部署。

OpenAI Embeddings：使用 GPT 系列模型，效果优秀但需要 API 调用，有成本和隐私考虑。

Sentence-BERT：基于 BERT 的句子嵌入模型，支持多语言，社区资源丰富。

E5 模型：微软开发的嵌入模型，在多项基准测试中表现优异。

### 4.5 检索增强技术

除了基本的向量检索，RAG 系统还可以采用多种增强技术来提高检索质量：

混合检索（Hybrid Search）：结合向量检索和关键词检索的优点，既考虑语义相似度，也考虑词汇匹配。

重排序（Reranking）：对初步检索结果使用更精确的模型进行重新排序，本项目使用 ONNX 运行的 Cross-Encoder 模型进行重排序。

查询改写：使用 LLM 将用户的自然语言问题改写为更适合检索的形式，提高召回率。

多轮检索：根据初步检索结果生成新的查询，进行迭代检索，逐步聚焦到最相关的内容。

### 4.6 本节小结

本章节详细介绍了 RAG 系统的核心技术，包括系统架构、向量数据库、分块策略、嵌入模型和检索增强技术。这些内容共同构成了一个完整的知识库问答系统。理解这些技术原理对于优化系统性能和解决实际问题非常重要。
