第一章：HTML 基础

HTML（HyperText Markup Language）是构建网页的标准标记语言。它定义了网页的结构和内容。

1.1 HTML 标签

HTML 使用标签来标记内容。常见的标签包括：

  • <h1> - <h6>：标题标签
  • <p>：段落标签
  • <a>：链接标签
  • <img>：图片标签

1.2 HTML 属性

HTML 标签可以包含属性，用于提供额外的信息。例如：

<a href="https://example.com">链接</a>

第二章：HTML5 新特性

HTML5 引入了许多新的语义化标签和 API。

2.1 语义化标签

HTML5 新增了以下语义化标签：

  • <header>：页眉
  • <nav>：导航
  • <main>：主要内容
  • <article>：文章
  • <section>：章节
  • <aside>：侧边栏
  • <footer>：页脚

2.2 多媒体支持

HTML5 原生支持音频和视频播放，无需第三方插件。

<video src="movie.mp4" controls></video>

<audio src="music.mp3" controls></audio>

第三章：CSS 样式

CSS（Cascading Style Sheets）用于控制网页的外观和布局。

3.1 选择器

CSS 选择器用于选中 HTML 元素。常见的选择器包括：

  • 元素选择器：p { color: red; }
  • 类选择器：.class { color: blue; }
  • ID 选择器：#id { color: green; }

3.2 盒模型

CSS 盒模型描述了元素的内容、内边距、边框和外边距。

理解盒模型对于网页布局非常重要。

3.2.1 内边距

内边距（padding）是内容与边框之间的空间。

3.2.2 边框

边框（border）是围绕内容的线条。

3.2.3 外边距

外边距（margin）是边框与其他元素之间的空间。

第四章：JavaScript 交互

JavaScript 用于实现网页的交互功能。

4.1 DOM 操作

DOM（Document Object Model）是 HTML 文档的编程接口。

通过 JavaScript 可以动态修改 DOM，实现页面的动态更新。

4.2 事件处理

JavaScript 可以响应用户的各种操作，如点击、输入、滚动等。

第五章：RAG 系统详解（L1级别测试）

RAG（Retrieval-Augmented Generation）是一种将信息检索与文本生成相结合的技术架构。它的核心思想是：在生成回答之前，先从知识库中检索相关的文档片段，然后将这些片段作为上下文提供给大语言模型，从而增强模型的回答能力和准确性。

5.1 系统架构

RAG 系统的主要优势包括：第一，无需重新训练模型即可更新知识库，大大降低了维护成本；第二，可以引用具体的知识来源，提高回答的可信度；第三，减少了模型的幻觉问题，因为回答基于实际检索到的文档；第四，可以处理私有或实时数据，而不受模型训练截止日期的限制。

RAG 系统的典型工作流程如下：用户提出问题后，系统首先将问题转换为向量表示，然后在向量数据库中检索最相关的文档片段。检索到的片段与原始问题一起被送入大语言模型，模型基于这些上下文生成最终的回答。整个过程实现了"检索-增强-生成"的闭环。

5.2 向量数据库技术

向量数据库是 RAG 系统的核心组件之一。它专门用于存储和检索高维向量数据。与传统的关系型数据库不同，向量数据库使用向量相似度作为检索依据，而不是精确匹配。常用的向量数据库包括：PostgreSQL with pgvector 扩展（本项目使用的方案）、Pinecone（托管式向量数据库）、Milvus（开源高性能向量数据库）、Weaviate（支持混合检索的开源数据库）、Chroma（轻量级嵌入式向量数据库）等。

向量相似度计算方法主要有：余弦相似度（Cosine Similarity）、欧几里得距离（Euclidean Distance）、点积（Dot Product）等。其中余弦相似度最为常用，因为它对向量的长度不敏感，只关注方向的一致性。

5.3 文本分块策略

文本分块是 RAG 系统中的关键预处理步骤。好的分块策略应该：保持语义完整性，避免将相关内容分散到不同分块；控制分块大小，使其适合向量模型的输入限制；保留上下文信息，便于后续检索和理解。

本项目实现了多种分块策略：MarkdownChunkStrategy 针对 Markdown 文档按标题层级分块；HtmlChunkStrategy 针对 HTML 文档按标签结构分块；CodeChunkStrategy 针对代码文件按类和函数定义分块；LineBasedChunkStrategy 针对日志和 CSV 文件按行分块；StructureAwareChunkStrategy 针对 PDF 和 DOCX 文档按段落分块；RecursiveChunkStrategy 作为通用兜底策略使用递归字符分割。

5.4 嵌入模型选择

嵌入模型负责将文本转换为向量表示。选择合适的嵌入模型对 RAG 系统的性能至关重要。常用的嵌入模型包括：BGE（BAAI General Embedding）系列，由北京智源人工智能研究院开发，支持中英文，本项目使用 BGE-small-zh 模型；OpenAI Embeddings，使用 GPT 系列模型，效果优秀但需要 API 调用；Sentence-BERT，基于 BERT 的句子嵌入模型；E5 模型，微软开发的嵌入模型。

5.5 检索增强技术

除了基本的向量检索，RAG 系统还可以采用多种增强技术来提高检索质量：混合检索（Hybrid Search）结合向量检索和关键词检索的优点；重排序（Reranking）对初步检索结果使用更精确的模型进行重新排序；查询改写使用 LLM 将用户的自然语言问题改写为更适合检索的形式；多轮检索根据初步检索结果生成新的查询，进行迭代检索。

  • 标题路径提取
  • HTML 标签剥离
