# 知识测验详细工作流

本文档描述知识测验技能的完整工作流，包括异常处理和边界情况。

## 完整工作流

```
用户请求 → 判断来源 → 收集素材 → 生成试题 → 持久化测验 → 返回结果
```

### 阶段一：解析用户意图

从用户消息中提取以下信息：

| 信息 | 必需 | 默认值 | 示例 |
|------|------|--------|------|
| 主题/关键词 | 是 | — | "数据结构"、"操作系统" |
| 素材来源 | 否 | notes | "我的笔记"、"网上搜" |
| 题型偏好 | 否 | 混合 | "只出选择题"、"填空题" |
| 题目数量 | 否 | 5 | "出10道题" |
| 难度 | 否 | mixed | "简单题"、"难题" |

如果用户没有明确指定，使用默认值，不要反复追问。

### 阶段二：收集素材

#### 来源一：用户笔记（search_knowledge_base）

调用方式：
```json
{
  "query": "用户指定的主题关键词"
}
```

注意事项：
- 查询关键词应与用户指定的主题一致
- 如果返回结果为空，告知用户笔记中没有相关内容，建议切换到网搜模式
- 如果返回结果较少（<3条），可以补充调用 web_search

#### 来源二：网络搜索（web_search）

调用方式：
```json
{
  "query": "搜索关键词",
  "maxResults": 5
}
```

注意事项：
- 搜索关键词应精炼，避免过于宽泛
- 搜索结果可能包含噪声，需要筛选与主题相关的内容
- 如果搜索失败（API Key 未配置等），告知用户联网搜索不可用，回退到笔记模式

#### 混合模式

当用户要求"综合出题"或笔记内容不足时：
1. 先调用 `search_knowledge_base` 获取笔记内容
2. 评估笔记内容是否足够覆盖主题
3. 不足时补充调用 `web_search`

### 阶段三：生成试题

#### Prompt 构建策略

生成试题时，系统提示词应包含以下要素：

1. **角色定义**：你是一个知识测验出题专家
2. **素材注入**：将收集到的笔记片段或搜索结果作为上下文
3. **格式约束**：必须输出合法 JSON，格式参照 question-types.md
4. **质量要求**：题目应覆盖素材的核心知识点，避免过于简单或晦涩

#### 题型分配建议

默认5道题的分配：
- 单选题 2 道
- 多选题 1 道
- 填空题 1 道
- 判断题 或 简答题 1 道

如果用户指定了题型偏好，按偏好调整。

#### 难度控制

| 难度 | 知识点选择 | 干扰项设计 |
|------|-----------|-----------|
| easy | 直接记忆型知识点 | 干扰项明显错误 |
| medium | 需要理解的知识点 | 干扰项有迷惑性 |
| hard | 需要综合应用的知识点 | 干扰项高度相似 |

### 阶段四：输出与校验

#### 输出格式

直接输出纯 JSON 字符串，不要包含 Markdown 代码块标记。

正确：
```json
{"title":"数据结构测验","questions":[...]}
```

错误：
````markdown
```json
{"title":"数据结构测验","questions":[...]}
```
````

#### 自检清单

生成 JSON 后，在内部验证以下项目（不输出验证过程）：

- [ ] JSON 语法合法（花括号/方括号闭合、无尾逗号）
- [ ] 顶层包含 `title` 和 `questions` 字段
- [ ] 每道题有 `id`、`type`、`stem`、`answer`、`explanation`
- [ ] 选择题有 `options` 数组，且选项以 A/B/C/D 开头
- [ ] 多选题的 `answer` 是数组
- [ ] 判断题的 `answer` 是"正确"或"错误"
- [ ] `id` 从 q1 开始连续递增
- [ ] 题目数量与用户要求一致

## 异常处理

### 素材不足

如果笔记和网搜都没有找到足够素材：
- 告知用户素材不足，无法生成高质量测验
- 建议用户先导入相关笔记或换一个主题

### JSON 输出异常

如果 LLM 输出的 JSON 格式有误：
- 后端会尝试容错解析（如去除 Markdown 代码块标记）
- 如果完全无法解析，返回错误提示，建议用户重新生成

### 工具调用失败

- `search_knowledge_base` 失败 → 回退到 `web_search`
- `web_search` 失败（API Key 未配置等）→ 仅使用笔记内容
- 两个都失败 → 告知用户当前无法生成测验

### 阶段五：持久化测验

生成完整的测验 JSON 后，**必须**调用 `save_exam` 工具保存到数据库：

- 传入参数：完整的测验 JSON（含 title、source_type、questions 数组）+ source_refs（素材来源引用列表）
- 必须传入 `source_refs`，记录素材来源引用（如笔记文档名、搜索结果URL），例如：`["RAG搭建笔记.md", "https://example.com/rag-guide"]`
- 工具返回：`{"examId": 123}`
- 在最终回答中引用 examId，告知用户测验已生成，格式如：
  "已为您生成《xxx》测验，共 N 道题。[查看测验](/quiz?examId={examId})"

**`save_exam` 调用示例**（必须严格参照此格式传参）：

```json
{
  "title": "数据结构基础测验",
  "source_type": "web_search",
  "questions": [
    {
      "type": "single_choice",
      "stem": "以下哪种数据结构最适合实现LRU缓存？",
      "options": ["A. 数组", "B. 单向链表", "C. 哈希表+双向链表", "D. 栈"],
      "answer": "C",
      "explanation": "哈希表提供O(1)查找，双向链表提供O(1)插入删除。",
      "difficulty": "medium"
    },
    {
      "type": "true_false",
      "stem": "二叉搜索树的中序遍历结果是有序序列",
      "answer": "正确",
      "explanation": "BST性质保证中序遍历按从小到大顺序访问。",
      "difficulty": "easy"
    }
  ],
  "source_refs": ["https://example.com/data-structures-guide"]
}
```

**关键约束**：
- `answer` 字段：单选/判断/填空/简答传字符串（如 `"C"` 或 `"正确"`）；多选传字符串数组（如 `["A","C"]`）
- `options` 字段：仅选择题需要，填空/判断/简答不要传此字段
- `stem` 和 `explanation` 中的文本不要包含未转义的双引号，如需引用请用单引号
- 确保 JSON 语法正确：所有字符串用双引号包裹、属性间用逗号分隔、无尾逗号

**重要**：
- 必须调用 `save_exam`，不能仅返回 JSON 文本而不持久化
- 如果 `save_exam` 返回失败，检查参数中的 JSON 语法（引号闭合、逗号分隔、无尾逗号），修正后再调用，不要盲目重试相同参数
- `source_type` 应根据实际使用的工具记录：仅笔记 → `notes`，仅网搜 → `web_search`，两者都用 → `mixed`
- **不要在回答中重复输出试题内容和答案**，答案不应在聊天界面暴露。只需提供简短提示和测验链接即可。

## 数据持久化

生成的测验数据将保存到以下数据库表：

| 表名 | 用途 |
|------|------|
| `exams` | 测验元信息（标题、来源类型、题目数量） |
| `exam_context` | 每道题的详细内容（题干、选项、答案、解析） |
| `exam_answers` | 用户答题记录（答案、得分） |

后端收到 JSON 后会解析并分别写入 `exams` 和 `exam_context` 表，`source_type` 根据实际使用的工具记录为 `notes`、`web_search` 或 `mixed`。
